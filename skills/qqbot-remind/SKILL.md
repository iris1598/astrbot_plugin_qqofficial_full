# QQ Bot 定时提醒

## ⚠️ 强制规则

**当用户提到「提醒」「闹钟」「定时」「X分钟/小时后」「每天X点」「叫我」等任何涉及延时或定时的请求时，你必须调用 `future_task` 工具，绝对不能只用自然语言回复说"好的，我会提醒你"！**

你没有内存或后台线程，口头承诺"到时候提醒"是无效的——只有调用 `future_task` 才能真正注册定时任务（AstrBot 核心 cron 调度，持久化存储，重启不丢失）。

---

## 工具：`future_task`（AstrBot 内置）

> 前置条件：WebUI 配置 `provider_settings.proactive_capability.add_cron_tools` 为开启（默认开启）。

| 参数 | 说明 | 示例 |
|------|------|------|
| `action` | 操作类型 | `"create"` / `"list"` / `"delete"` / `"edit"` |
| `note` | **写给未来你自己的执行指令**（必填） | 见下方提醒模板 |
| `run_once` | 一次性任务设 `true`，配合 `run_at` | `true` |
| `run_at` | **ISO 8601 绝对时间**（含时区偏移） | `"2026-09-06T20:30:00+08:00"` |
| `cron_expression` | 5 字段 crontab（周期任务必填，与 run_once 二选一） | `"0 8 * * *"` |
| `name` | 任务标签（可选） | `"喝水提醒"` |
| `job_id` | delete/edit 时必填，从 list 结果获取 | — |

### ⏰ 时间换算（重要，最容易出错的环节）

`future_task` 只接受**绝对时间**。收到"5分钟后""明天早上8点"这类相对说法时，**必须先确定当前时间**（以你上下文中给出的当前时间/时区为准，QQ 用户通常为 Asia/Shanghai UTC+8），再加上延迟量，换算成带 `+08:00` 偏移的 ISO 字符串后填入 `run_at`。宁可先向用户复述换算结果（"今晚 20:30 提醒你喝水，OK？"）也不要算错时间。

### 📝 提醒类任务的 note 模板（照此写）

```
你是一个暖心的提醒助手。请用温暖、有趣的方式提醒用户：{提醒内容}。要求：(1) 不要解释你是谁 (2) 直接输出一条暖心的提醒消息 (3) 可以加一句简短的鸡汤或关怀的话 (4) 控制在2-3句话以内 (5) 用emoji点缀。生成该提醒文案后，必须调用 send_message_to_user 工具，把提醒发送到当前会话。
```

到点后 AstrBot 会唤醒你执行这条 `note`，届时按其中的指示调用 `send_message_to_user` 完成投递（目标会话已自动绑定为你创建任务时所在的 QQ 会话）。

## 示例

用户说："5分钟后提醒我喝水"（假设当前时间 2026-09-06 20:25 +08:00）

1. 调用 `future_task`：
   ```json
   {
     "action": "create",
     "name": "喝水提醒",
     "run_once": true,
     "run_at": "2026-09-06T20:30:00+08:00",
     "note": "你是一个暖心的提醒助手。请用温暖、有趣的方式提醒用户：该喝水了。要求：(1) 不要解释你是谁 (2) 直接输出一条暖心的提醒消息 (3) 可以加一句简短的鸡汤或关怀的话 (4) 控制在2-3句话以内 (5) 用emoji点缀。生成该提醒文案后，必须调用 send_message_to_user 工具，把提醒发送到当前会话。"
   }
   ```
2. 回复用户：`⏰ 好的，5分钟后（今晚20:30）提醒你喝水~`

用户说："每天早上8点提醒我打卡"

```json
{
  "action": "create",
  "name": "打卡提醒",
  "cron_expression": "0 8 * * *",
  "note": "（同上模板，提醒内容替换为『记得打卡』）"
}
```

## cron 表达式速查

| 场景 | expr |
|------|------|
| 每天早上8点 | `"0 8 * * *"` |
| 每天晚上10点 | `"0 22 * * *"` |
| 工作日早上9点 | `"0 9 * * mon-fri"` |
| 每周一早上9点 | `"0 9 * * mon"` |
| 每周末上午10点 | `"0 10 * * sat,sun"` |
| 每小时整点 | `"0 * * * *"` |

> 优先使用具名星期（`mon-fri`、`sat,sun`），比数字更可靠。

## AI 决策指南

| 用户说法 | action | 参数 |
|----------|--------|------|
| "5分钟后提醒我喝水" | `create` | `run_once=true` + `run_at`（换算绝对时间） |
| "明天早上8点提醒开会" | `create` | `run_once=true` + `run_at` |
| "每天8点提醒我打卡" | `create` | `cron_expression="0 8 * * *"` |
| "工作日早上9点提醒" | `create` | `cron_expression="0 9 * * mon-fri"` |
| "我有哪些提醒" | `list` | — |
| "取消喝水提醒" | `list` → `delete` | `job_id` |
| "修改提醒时间" | `list` → `edit` | `job_id` + 新参数 |
| "提醒我"（无时间） | **需追问** | — |

纯相对时间（"5分钟后"、"1小时后"）可直接换算，无需确认；时间模糊或缺失时需追问。

## 回复模板

- 一次性：`⏰ 好的，{时间}后提醒你{内容}~`（建议附上换算出的绝对时间）
- 周期：`⏰ 收到，{周期}提醒你{内容}~`
- 查询无结果：`📋 目前没有提醒哦~ 说"5分钟后提醒我xxx"试试？`
- 删除成功：`✅ 已取消"{名称}"`
